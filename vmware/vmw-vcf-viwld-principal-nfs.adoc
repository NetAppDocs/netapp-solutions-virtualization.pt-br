= Use um datastore NFS no ONTAP como storage primário para um domínio de workload VCF
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Neste caso de uso, descrevemos o procedimento para configurar um datastore NFS no ONTAP como a solução de storage primário para um domínio de carga de trabalho do VMware Cloud Foundation (VCF). Este procedimento resume os componentes necessários, as etapas de configuração e o processo de implantação.



[[benefits-of-nfs]]
== Benefícios do NFS

*Simplicidade e facilidade de uso:* O NFS é simples de configurar e gerenciar, o que o torna uma excelente escolha para ambientes que exigem compartilhamento de arquivos rápido e fácil.

*Escalabilidade:* a arquitetura do ONTAP permite que o NFS seja dimensionado de forma eficiente, dando suporte às crescentes necessidades de dados sem mudanças significativas na infraestrutura.

*Flexibilidade:* O NFS oferece suporte a uma ampla variedade de aplicativos e cargas de trabalho, o que o torna versátil para vários casos de uso, incluindo ambientes virtualizados.



[[scenario-overview]]
== Visão geral do cenário

Este cenário abrange as seguintes etapas de alto nível:

* Crie uma máquina virtual de armazenamento (SVM) com interface lógica (LIFs) para tráfego NFS
* Verifique a rede da máquina virtual de armazenamento ONTAP (SVM) e se uma interface lógica (LIF) está presente para transportar o tráfego NFS.
* Crie uma política de exportação para permitir que os hosts vSphere acessem o volume NFS.
* Crie um volume NFS no sistema de armazenamento ONTAP .
* Crie um pool de rede para tráfego NFS e vMotion no SDDC Manager.
* Comissione hosts no vCenter para uso em um domínio de carga de trabalho VCF.
* Implemente um domínio de carga de trabalho VCF no VCF Ops usando um datastore NFS como storage primário.
* Certifique-se de que a imagem do cluster inclua o NetApp NFS Plug-in para VMware VAAI.



NOTE: Esta solução é aplicável para plataformas ONTAP que suportam storage NFS, incluindo NetApp AFF, AFX e FAS.



[[prerequisites]]
== Pré-requisitos

Os seguintes componentes e configurações são usados neste cenário:

* NetApp AFF, AFX ou sistema de storage FAS com uma máquina virtual de storage (SVM) configurada para permitir tráfego NFS.
* A interface lógica (LIF) foi criada na rede IP que transportará o tráfego NFS e está associada ao SVM.
* A implantação do domínio de gerenciamento do VCF foi concluída e a interface do Operations Manager está acessível.
* Pelo menos 2 vSphere hosts configurados para comunicação na rede de gerenciamento do VCF.
* Endereços IP reservados para tráfego de armazenamento vMotion e NFS na VLAN ou segmento de rede estabelecido para essa finalidade.



NOTE: Ao implantar um Domínio de Carga de Trabalho VCF, o VCF valida a conectividade com o servidor NFS. Isso é feito usando o adaptador de gerenciamento nos hosts vSphere antes que qualquer adaptador vmkernel adicional seja adicionado com o endereço IP do NFS. Portanto, é necessário garantir que 1) a rede de gerenciamento seja roteável para o servidor NFS ou 2) uma LIF para a rede de gerenciamento tenha sido adicionada à SVM que hospeda o volume do datastore NFS, para garantir que a validação possa prosseguir.

Para obter informações sobre como configurar sistemas de armazenamento ONTAP , consulte olink:https://docs.netapp.com/us-en/ontap["Documentação do ONTAP 9"] centro.

Para obter informações sobre como configurar o VCF, consulte link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["Documentação do VMware Cloud Foundation"].

Para obter mais informações sobre o uso do NFS com clusters vSphere, consulte olink:vmw-vvf-overview.html["Guia de referência do NFS v3 para vSphere 8"] .

[[deployment-steps]]
== Etapas de implantação

Para implantar um domínio de carga de trabalho VCF com um datastore NFSv3 como storage primário, siga estas etapas:

.Verificar rede para ONTAP SVM
[%collapsible%open]
====
Verifique se as interfaces lógicas necessárias foram estabelecidas para a rede que transportará o tráfego NFS entre o cluster de storage ONTAP e o Workload Domain.

. No ONTAP System Manager, navegue até *Storage VMs* no menu à esquerda e clique na SVM que será usada para o tráfego NFS. Na guia *Overview*, em *Network interfaces*, clique no número acima do rótulo *NFS*. Na lista, verifique se os endereços IP da LIF necessários estão listados.
+
image:vmw-vcf-viwld-principal-nfs-001.png["Verifique as LIFs NFS para SVM"]



Como alternativa, verifique os LIFs associados a uma SVM na CLI do ONTAP com o seguinte comando:

[source, cli]
----
network interface show -vserver <SVM_NAME>
----
. Verifique se os hosts vSphere conseguem se comunicar com o servidor NFS do ONTAP. Faça login no host vSphere via SSH e execute um ping no LIF da SVM:


[source, cli]
----
vmkping <IP Address>
----

NOTE: Ao implantar um Domínio de Carga de Trabalho, o VCF valida a conectividade com o servidor NFS. Isso é feito usando o adaptador de gerenciamento nos hosts vSphere antes que qualquer adaptador vmkernel adicional seja adicionado com o endereço IP do NFS. Portanto, é necessário garantir que 1) a rede de gerenciamento seja roteável para o servidor NFS ou 2) uma LIF para a rede de gerenciamento tenha sido adicionada à SVM que hospeda o volume do datastore NFS, para garantir que a validação possa prosseguir.

====
.Criar política de exportação para compartilhar volume NFS
[%collapsible%open]
====
Crie uma política de exportação no ONTAP System Manager para definir o controle de acesso para volumes NFS.

. No ONTAP System Manager, clique em *VMs de armazenamento* no menu à esquerda e selecione uma SVM na lista.
. Na aba *Configurações* localize *Políticas de Exportação* e clique na seta para acessar.
+
image:vmw-vcf-viwld-principal-nfs-002.png["Políticas de Exportação de Acesso"]

+
{nbsp}

. Após clicar em Adicionar, a janela *Nova política de exportação* será aberta. Adicione um nome para a política, clique no botão *Adicionar novas regras* e depois no botão *+Adicionar* para começar a adicionar uma nova regra.
+
image:vmw-vcf-viwld-principal-nfs-003.png["Nova política de exportação"]

+
{nbsp}

. Preencha os endereços IP, o intervalo de endereços IP ou a rede que você deseja incluir na regra. Desmarque as caixas *SMB/CIFS* e *FlexCache* e faça as seleções para os detalhes de acesso abaixo. Selecionar as caixas UNIX é suficiente para o acesso do host vSphere.
+
image:vmw-vcf-viwld-principal-nfs-004.png["Salvar nova regra"]

+

NOTE: Ao implantar um Domínio de Carga de Trabalho, o VCF valida a conectividade com o servidor NFS. Isso é feito usando o adaptador de gerenciamento nos vSphere hosts antes que qualquer adaptador vmkernel adicional seja adicionado com o endereço IP do NFS. Portanto, é necessário garantir que a política de exportação inclua a rede de gerenciamento do VCF para permitir que a validação prossiga.

. Depois que todas as regras forem inseridas, clique no botão *Salvar* para salvar a nova Política de Exportação.
. Como alternativa, você pode criar políticas e regras de exportação no ONTAP CLI.  Consulte as etapas para criar uma política de exportação e adicionar regras na documentação do ONTAP .
+
** Use o ONTAP CLI paralink:https://docs.netapp.com/us-en/ontap/nfs-config/create-export-policy-task.html["Crie uma política de exportação"] .
** Use o ONTAP CLI paralink:https://docs.netapp.com/us-en/ontap/nfs-config/add-rule-export-policy-task.html["Adicionar uma regra a uma política de exportação"] .




====
.Criar volume NFS
[%collapsible%open]
====
Crie um volume NFS no sistema de armazenamento ONTAP para ser usado como um armazenamento de dados na implantação do Domínio de Carga de Trabalho.

. No ONTAP System Manager, navegue até *Armazenamento > Volumes* no menu à esquerda e clique em *+Adicionar* para criar um novo volume.
+
image:vmw-vcf-viwld-principal-nfs-005.png["Adicionar novo volume"]

+
{nbsp}

. Adicione um nome para o volume, preencha a capacidade desejada e selecione a VM de armazenamento que hospedará o volume.  Clique em *Mais opções* para continuar.
+
image:vmw-vcf-viwld-principal-nfs-006.png["Adicionar detalhes de volume"]

+
{nbsp}

. Em Permissões de acesso, selecione a Política de exportação que inclui a rede de gerenciamento do VCF ou endereço IP e endereços IP da rede NFS que serão usados para validação do servidor NFS e do tráfego NFS.
+
image:vmw-vcf-viwld-principal-nfs-007.png["Adicionar detalhes de volume"]

+
+ {nbsp}

+

NOTE: Ao implantar um Domínio de Carga de Trabalho VCF, o VCF valida a conectividade com o servidor NFS. Isso é feito usando o adaptador de gerenciamento nos hosts vSphere antes que qualquer adaptador vmkernel adicional seja adicionado com o endereço IP do NFS. Portanto, é necessário garantir que 1) a rede de gerenciamento seja roteável para o servidor NFS ou 2) uma LIF para a rede de gerenciamento tenha sido adicionada à SVM que hospeda o volume do datastore NFS, para garantir que a validação possa prosseguir.

. Alternativamente, volumes NFS podem ser criados na CLI do ONTAP. Para mais informações, consulte o comando link:https://docs.netapp.com/us-en/ontap-cli/volume-create.html["criar volume"] na documentação de comandos do ONTAP.

[[vcf-workload-domain-default-cluster]]
=== Domínio de workload VCF - cluster padrão

Após o domínio de gerenciamento estar configurado e em funcionamento, o domínio de workload do VCF pode ser criado:

* Usando a interface do usuário do VCF Ops. Os hosts vSphere são comissionados no vCenter e o pool de rede é configurado. Use o System Manager ou a API do ONTAP para exportar o volume NFS para os hosts vSphere.
* Importe um ambiente vSphere existente como novo domínio de carga de trabalho. O ONTAP tools for VMware vSphere, o System Manager ou a ONTAP API podem ser usados para implantar o datastore NFSv3 ou NFS4.1 no cluster vSphere.




[[vcf-workload-domain-additional-cluster]]
=== Domínio de workload VCF - cluster adicional

Para expandir o domínio de carga de trabalho com um cluster adicional, consulte  https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/expand-a-workload-domain/add-a-cluster-to-a-workload-domain-using-the-sddc-manager-ui.html["Adicionar um cluster SDDC a um domínio VCF"].

Em linhas gerais, os passos para adicionar um cluster adicional ao domínio de carga de trabalho são os seguintes: * Certifique-se de que os hosts estejam comissionados e os pools de rede estejam configurados no vCenter. * O volume NFS deve ser provisionado no sistema de storage ONTAP e exportado para os hosts no cluster adicional. * O volume NFS deve ser montado em um dos hosts vSphere no cluster adicional. * Crie um novo cluster SDDC no domínio de carga de trabalho no vCenter e siga o assistente para adicionar o cluster adicional ao domínio de carga de trabalho.
