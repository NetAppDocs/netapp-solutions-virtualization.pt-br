[role="lead"]
NetApp ONTAP integra-se ao VMware Cloud Foundation (VCF) para fornecer uma solução de storage unificado que suporta protocolos de bloco, arquivo e objeto. As funcionalidades de alocação a vários clientes do ONTAP permitem que as organizações consolidem cargas de trabalho e simplifiquem o gerenciamento, enquanto oferecem proteção e disponibilidade de dados de nível empresarial. Este documento fornece uma visão geral do VCF e de como NetApp ONTAP pode ser usado para aprimorar funcionalidades de storage em um ambiente VCF.



[[introduction]]
== Introdução

O VCF permite que as organizações implementem e gerenciem um ambiente de nuvem privada com facilidade. De forma integrada, ele fornece máquinas virtuais, Kubernetes, contêineres e redes como serviço, e permite expandir para oferecer outros serviços como itens de catálogo em um portal de autoatendimento. Ao utilizar NetApp ONTAP como a solução de storage dentro do VCF, as organizações podem alcançar maior flexibilidade, escalabilidade e eficiência no gerenciamento de suas cargas de trabalho.



[[introduction-to-netapp-ontap]]
== Introdução ao NetApp ONTAP

NetApp ONTAP é um software de gerenciamento de dados abrangente que oferece funcionalidades avançadas de storage em uma ampla linha de produtos. O ONTAP está disponível como storage definido por software, como um serviço próprio por meio dos principais provedores de nuvem e como o sistema operacional de storage para NetApp ASA (Desagregado para Otimização de Blocos), AFX (Desagregado para dados não estruturados), AFF e FAS (Unificado). O ONTAP oferece alto desempenho e baixa latência para uma variedade de casos de uso, incluindo virtualização VMware, sem criar silos. De forma semelhante à criação de uma máquina virtual em computação, o ONTAP permite a criação de máquinas virtuais de storage (SVMs) que podem ser usadas para criar e gerenciar recursos de storage. O ONTAP fornece uma solução de storage unificado que suporta múltiplos protocolos, incluindo NFS, SMB, iSCSI, FC, NVMe/TCP, NVMe/FC e NVMe/RDMA. Essa flexibilidade permite que as organizações consolidem cargas de trabalho e simplifiquem o gerenciamento, ao mesmo tempo que fornecem proteção e disponibilidade de dados de nível empresarial.



[[introduction-to-vmware-cloud-foundation]]
== Introdução ao VMware Cloud Foundation

O VMware Cloud Foundation (VCF) permite que as organizações criem nuvens privadas virtuais onde podem consumir máquinas virtuais, clusters Kubernetes, contêineres, redes e storage como serviço, seja para cargas de trabalho de IA, DevOps ou cargas de trabalho tradicionais baseadas em máquinas virtuais.

O VCF é implementado em ambientes novos ou para expandir um ambiente vSphere existente para uma nuvem privada completa. Um conjunto de hosts de computação forma um cluster vSphere, um grupo de clusters vSphere forma um domínio VCF, e um grupo de domínios VCF forma uma instância VCF. Uma frota consiste em uma ou mais instâncias VCF. Ambientes de nuvem privada VCF são criados usando uma ou mais frotas. A operação e a automação são gerenciadas no nível da frota, enquanto a instância VCF é a unidade de implementação.

Um namespace do vSphere é utilizado para definir limites de recursos para cargas de trabalho. Uma zona do vSphere é uma coleção de clusters do vSphere que pode ser usada para fornecer alta disponibilidade e funcionalidades de recuperação de desastres para cargas de trabalho em execução na zona.

image:vmware-vcf-overview-components.png["Componentes do VMware Cloud Foundation"]

Na automação do VCF, uma região é um conjunto de zonas do vSphere de um ou mais domínios do VCF que compartilham a mesma infraestrutura NSX. Uma organização é um agrupamento lógico de usuários e recursos de uma ou mais regiões. A organização pode ser subdividida em vários projetos, cada um com seu próprio gateway de trânsito e conexão externa. Um projeto possui um ou mais namespaces e pode ser usado para fornecer isolamento e alocação de recursos para cargas de trabalho em execução no projeto.

Os namespaces são a unidade fundamental para alocação de recursos dentro de um projeto. Cada namespace corresponde a uma nuvem privada virtual (VPC) e pode ser usado para fornecer isolamento e alocação de recursos para cargas de trabalho em execução no namespace.

Os namespaces são criados com uma VPC dedicada ou uma VPC compartilhada. Uma VPC dedicada é uma VPC dedicada a um único namespace, enquanto uma VPC compartilhada é uma VPC que pode ser usada por vários namespaces. As sub-redes são criadas dentro de uma VPC onde as cargas de trabalho são implantadas.

O armazenamento é consumido por políticas de Storage Policy Based Management (SPBM) definidas em vCenter. O SPBM pode ser criado com um conjunto de regras que definem os requisitos de armazenamento para uma carga de trabalho. Os datastores são normalmente etiquetados e utilizados para criar políticas de armazenamento que atendam às necessidades específicas de diferentes cargas de trabalho.

As cargas de trabalho que exigem regras de afinidade e antiafinidade são gerenciadas por políticas de infraestrutura, que utilizam as políticas de computação do vCenter para definir a alocação de cargas de trabalho em hosts ou clusters específicos. As políticas de infraestrutura podem ser usadas para garantir que as cargas de trabalho sejam alocadas em hosts ou clusters específicos com base em seus requisitos.



[[vcf-domains]]
== Domínios VCF

Domínios são uma construção fundamental dentro do VCF que permite a organização de recursos em grupos distintos e independentes.  Os domínios ajudam a organizar a infraestrutura de forma mais eficaz, garantindo que os recursos sejam utilizados com eficiência.  Cada domínio é implantado com seus próprios elementos de computação, rede e armazenamento.

image:vmware-vcf-overview-domains.png["Domínios de nuvem VMware"]

Existem dois tipos principais de domínios com VCF:

* *Domínio de gerenciamento* – O domínio de gerenciamento inclui componentes responsáveis pelas funções principais do ambiente VCF. Os componentes lidam com tarefas essenciais, como provisionamento de recursos, monitoramento, manutenção e incluem integrações de plug-ins de terceiros, como NetApp ONTAP Tools for VMware. Os domínios de gerenciamento podem ser implementados usando o VCF Installer Appliance para garantir que as melhores práticas sejam seguidas, ou um ambiente vCenter existente pode ser convertido em um domínio de gerenciamento VCF.
* *Domínio de Carga de Trabalho* – Os domínios de carga de trabalho são projetados para serem conjuntos de recursos dedicados a uma necessidade operacional, carga de trabalho ou organização específica. Os domínios de carga de trabalho são implantados facilmente por meio do OPS Manager, ajudando a automatizar uma série de tarefas complexas. Até 24 domínios de carga de trabalho podem ser provisionados em um ambiente VCF, cada um representando uma unidade de infraestrutura pronta para uso. Cada domínio de carga de trabalho possui sua própria infraestrutura NSX ou compartilha uma existente, dependendo se a implantação é de região única ou multirregional.




[[storage-with-vcf]]
== Armazenamento com VCF

O armazenamento que eles consomem é essencial para a funcionalidade dos domínios.  Embora o VCF inclua capacidade vSAN baseada em núcleo de CPU para casos de uso hiperconvergentes, ele também oferece suporte a uma ampla gama de soluções de armazenamento externo.  Essa flexibilidade é crucial para empresas que têm investimentos significativos em matrizes de armazenamento existentes ou precisam oferecer suporte a protocolos além do que o vSAN oferece.  O VMware oferece suporte a vários tipos de armazenamento com VCF.

Existem dois tipos principais de armazenamento com VCF:

* *Armazenamento principal* – Este tipo de armazenamento é provisionado automaticamente como parte da implantação inicial de um novo domínio VCF ou como parte da convergência ou importação de um vCenter existente. O instalador do VCF oferece suporte a VSAN, VMFS em FC e NFS como parte de uma implantação nova, enquanto outros tipos de armazenamento compatíveis, incluindo VMFS em iSCSI e NVMe-oF, podem ser definidos como armazenamento principal como parte da convergência ou importação de um vCenter existente. O ONTAP Tools for VMware vSphere pode ser usado apenas para convergência ou importação de um vCenter existente para implantar o armazenamento principal de um domínio VCF. Qualquer datastore criado como parte da implantação de um cluster adicional ou como parte da expansão de um domínio é considerado armazenamento principal. O armazenamento principal é usado para hospedar os componentes de gerenciamento do VCF, incluindo o vCenter, o NSX Manager e o SDDC Manager, bem como as cargas de trabalho em execução no domínio.
* *Armazenamento suplementar* – O armazenamento suplementar é qualquer datastore provisionado após a implantação inicial de um domínio VCF ou após a convergência ou importação de um ambiente vCenter existente. O armazenamento suplementar pode ser criado usando o ONTAP Tools for VMware vSphere para implantar datastores para um domínio VCF. O armazenamento suplementar é criado para atender a necessidades adicionais de capacidade, requisitos de desempenho ou para suportar cargas de trabalho específicas que exigem diferentes características de storage. O armazenamento suplementar também pode ser criado para criar clusters estendidos para alta disponibilidade.

[[why-ontap-for-vcf]]
== Por que ONTAP para VCF

Além dos casos de uso que envolvem proteção de investimento e suporte a vários protocolos, há muitos motivos adicionais para aproveitar o armazenamento compartilhado externo dentro de um domínio de carga de trabalho VCF.  Pode-se presumir que o armazenamento provisionado para um domínio de carga de trabalho seja meramente um repositório para hospedar VMs e contêineres.  No entanto, as necessidades da organização muitas vezes superam as capacidades da capacidade licenciada e exigem armazenamento empresarial.  O armazenamento fornecido pelo ONTAP, alocado em domínios dentro do VCF, é fácil de implantar e oferece uma solução de armazenamento compartilhado preparada para o futuro.

image:why-ontap-for-vmware-002.png["Por que ONTAP para VCF"]

Para obter mais informações sobre os principais benefícios do ONTAP para VMware VCF identificados abaixo, consultelink:vmw-getting-started-overview.html#why-ontap-for-vmware["Por que ONTAP para VMware"] .

* Flexibilidade no primeiro dia e à medida que você cresce
* Descarregue tarefas de armazenamento para o ONTAP
* Melhor eficiência de armazenamento da categoria
* Disponibilidade de dados de nível empresarial
* Operações eficientes de backup e recuperação
* Capacidades holísticas de continuidade de negócios

[[summary]]
== Resumo

A ONTAP fornece uma plataforma que atende a todos os requisitos de carga de trabalho, oferecendo soluções personalizadas de armazenamento em bloco e ofertas unificadas para permitir resultados mais rápidos para VMs e aplicativos de maneira confiável e segura.  O ONTAP incorpora técnicas avançadas de redução e movimentação de dados para minimizar o espaço ocupado pelo data center, ao mesmo tempo em que garante disponibilidade em nível empresarial para manter cargas de trabalho críticas on-line.  Além disso, a AWS, o Azure e o Google oferecem suporte ao armazenamento externo com tecnologia NetApp para aprimorar o armazenamento vSAN em clusters baseados em nuvem da VMware como parte de suas ofertas VMware-in-the-Cloud.  No geral, os recursos superiores do NetApp o tornam uma escolha mais eficaz para implantações do VMware Cloud Foundation.
