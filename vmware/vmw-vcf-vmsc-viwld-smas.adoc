= Configure um cluster estendido para um domínio de carga de trabalho usando o SnapMirror active sync (SAN e NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Neste caso de uso, descrevemos o procedimento para configurar um cluster estendido para um domínio de carga de trabalho usando SnapMirror active sync com o ONTAP tools for VMware vSphere (o ONTAP tools 10.6 suporta FC e iSCSI). O ONTAP suporta SnapMirror active sync tanto para SAN (com iSCSI, Fibre Channel e NVMe over Fabrics) quanto para NAS (NFSv3 e NFSv4.1).

image:vmw-vcf-vmsc-viwld-smas-001.png["Stretch cluster para VCF com SnapMirror active sync"]

Tanto as configurações de cluster estendido uniforme quanto não uniforme são suportadas para SAN. No caso de NAS, é uma configuração ativo-passivo com o ONTAP 9.19.1.

[NOTE]
====
As configurações de proximidade do host são usadas com a configuração de multipath para garantir a seleção do caminho ideal para o tráfego de storage. As configurações de proximidade do host são configuradas no igroup no caso de SCSI e no subsistema no caso de NVMe-oF. Por exemplo, na configuração de Uniform host access, o host tem acesso a ambos os sistemas de storage no stretched cluster. Na configuração de multipath, os caminhos ideais e não ideais são configurados com base nas configurações de proximidade do host.

====


[[scenario-overview]]
== Visão geral do cenário

Os datastores no domínio de workload do VCF podem ser protegidos com o SnapMirror active sync para fornecer uma solução de stretch cluster. A proteção é habilitada no nível do datastore (grupo de consistência) para SAN e protegida no nível do SVM para NAS.



[[prerequisites]]
== Pré-requisitos

.Armazenamento principal no domínio de carga de trabalho
[%collapsible%open]
====
O domínio de carga de trabalho pode ser criado por importação ou por criação usando a ferramenta VCF Ops.

. Crie um domínio de carga de trabalho com qualquer protocolo compatível.
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-vcenter.html["Registre o domínio de carga de trabalho vCenter no gerenciador de ferramentas ONTAP para implantar o plugin vCenter"]
. link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/configure/add-storage-backend.html["Registre sistemas de armazenamento em ferramentas ONTAP"]
. Para os datastores iSCSI e FC, consulte link:https://docs.netapp.com/us-en/ontap-tools-vmware-vsphere-10/protect/protect-multiple-ds.html["Proteja o datastore do vSphere com as ONTAP tools"]
. Para os datastores NVMe-oF e NFS, confira a demonstração em vídeo abaixo para ver as etapas para proteger os datastores no domínio de carga de trabalho com o SnapMirror active sync.


====
.Armazenamento suplementar no domínio de carga de trabalho
[%collapsible%open]
====
Depois que o domínio de carga de trabalho estiver em funcionamento, datastores adicionais podem ser criados e protegidos usando as ferramentas do ONTAP. Para mais detalhes sobre a sincronização ativa do SnapMirror, consulte https://docs.netapp.com/us-en/ontap/snapmirror-active-sync/index.html#benefits["Saiba mais sobre ONTAP SnapMirror active sync"]


TIP: Com o ONTAP tools 10.6 e versões posteriores, você pode proteger os datastores no domínio de carga de trabalho com o SnapMirror active sync. Consulte a demonstração em vídeo abaixo para ver as etapas para proteger os datastores no domínio de carga de trabalho com o SnapMirror active sync.

====
