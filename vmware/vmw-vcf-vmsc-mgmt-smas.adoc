= Configure um cluster estendido para um domínio de gerenciamento VCF usando o SnapMirror Active Sync (SAN e NAS)
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Neste caso de uso, descrevemos o procedimento para usar ONTAP tools for VMware vSphere para configurar um cluster estendido para um domínio de gerenciamento VCF.  Este procedimento inclui a implantação de hosts vSphere e vCenter Server, a instalação de ferramentas ONTAP , a proteção de datastores com o SnapMirror Active Sync, a migração de VMs para datastores protegidos e a configuração de armazenamento suplementar.

image:vmw-vcf-vmsc-mgmt-smas-001.png["Stretch Cluster com ONTAP para domínio de gerenciamento de VCF"]

Tanto as configurações de cluster estendido uniforme quanto não uniforme são suportadas para SAN. No caso de NAS, é uma configuração ativo-passivo com o ONTAP 9.19.1.

[NOTE]
====
As configurações de proximidade do host são usadas com a configuração de multipath para garantir a seleção do caminho ideal para o tráfego de storage. As configurações de proximidade do host são configuradas no igroup no caso de SCSI e no subsistema no caso de NVMe-oF. Por exemplo, na configuração de Uniform host access, o host tem acesso a ambos os sistemas de storage no stretched cluster. Na configuração de multipath, os caminhos ideais e não ideais são configurados com base nas configurações de proximidade do host.

====


[[scenario-overview]]
== Visão geral do cenário

A solução de cluster estendido pode ser implementada no cluster padrão ou em cluster adicional nos domínios de gerenciamento ou de carga de trabalho do VCF. As ONTAP tools 10.6 oferecem suporte à proteção de datastore com SnapMirror active sync para datastores VMFS nos protocolos iSCSI e FC. O ONTAP oferece suporte ao SnapMirror active sync para SAN (com iSCSI, FC, NVMe-oF) e NAS (NFS v3 e NFSv4.1). Para protocolos SAN, a proteção é realizada no nível de grupo de consistência, enquanto para NAS é realizada no nível de SVM. O diagrama a seguir ilustra a solução de cluster estendido para um domínio de gerenciamento VCF com as ONTAP tools para VMFS com FC.

image:vmware-vcf-asa-mgmt-stretchcluster-002.png["Stretch Cluster com ONTAP para domínio de gerenciamento de VCF"]

.Armazenamento principal no domínio de gerenciamento
[%collapsible%open]
====
. Implemente o domínio de gerenciamento VCF com qualquer protocolo compatível.
+
.. Para VMFS em FC e NFSv3, a ferramenta VCF Installer é usada diretamente. No caso de iSCSI, NVMe-oF e NFSv4.1, é necessário configurar o vCenter e, posteriormente, usar a ferramenta VCF Installer para implantar o domínio de gerenciamento. Para mais informações, consulte link:vmw-vcf-migrate.html["Implantação do domínio de gerenciamento VCF com iSCSI, NVMe-oF e NFSv4.1"]


. Implantar ONTAP tools for VMware vSphere
. Implantar o plugin SnapCenter para VMware vSphere (opcional)
. Proteja o datastore.
+
.. Para iSCSI e FC, o ONTAP tools 10.6 ou superior é usado para proteger os datastores. No caso de NVMe-oF e NFSv4.1, utilize o System Manager para proteger os datastores. Para referência, confira o vídeo de demonstração abaixo para NVMe/TCP e NFS.




====
.Armazenamento suplementar no domínio de gerenciamento
[%collapsible%open]
====
Após o domínio de gerenciamento estar em funcionamento, datastores adicionais podem ser criados usando o ONTAP tools 10.6 ou superior e protegidos com o SnapMirror active sync para iSCSI e FC. Para NVMe-oF e NFS, consulte o vídeo de demonstração abaixo como referência, pois a demonstração é realizada em um domínio de carga de trabalho, mas as mesmas etapas podem ser seguidas para o domínio de gerenciamento também.

====
